# union-skill 使用与适配方法

## 用途与位置

[union-skill](../skills/union-skill/SKILL.md) 用于指导 AI 为不同架构的 Minecraft 皮肤站评估和实现 MUA Union 成员适配。它包含协议基线、架构判断与验证方法，不绑定本机路径，也不要求其他皮肤站采用 Element Skin 的数据库或 OAuth 权限名称。

当前为首版技能草案，随本仓库维护。结构验证只能证明技能可解析；跨架构决策质量还需要在真实适配任务中持续复核。它不是已实现的其他皮肤站适配器。

## 使用方式

在支持本地技能的 AI 工具中，按照该工具的技能加载方式使用完整目录。Codex 可将此目录复制到自己的 skills 目录，再通过 $union-skill 调用；当前初始化没有修改全局技能目录。

也可以在新任务中明确要求 AI 读取本仓库的 SKILL.md 和它链接的参考文件。工具未加载该目录时，单独写 $union-skill 不保证已实际读取技能。

建议提供目标仓库位置、希望采用的适配方式和当前阶段，例如：

> 使用 union-skill 检查这个 Java 皮肤站。保留原账号系统，通过独立网关接入 Union，先实现无冲突角色的联合进服。先读取真实认证与会话代码，说明需要补充的最小能力，再按仓库规范实现和测试。

只做研判或文档时明确写出范围：

> 阅读该 Python 皮肤站并使用 union-skill 完成适配设计。本次只交付能力矩阵、网关方案和联调计划，不编写运行代码。

不需要用户提供不可获得的中心源码。已有参考客户端足以形成有边界的适配实现；真实登记和中心转发作为独立验收阶段。

## 期望产物

- 按实际 endpoint 和代码定位填写能力矩阵。
- 说明登录权威、进服会话权威、签名持有者和 UUID 映射位置。
- 保留目标技术栈，选择原生、网关或最小扩展；缺少安全会话时明确指出。
- 实现范围内的完整链路与失败状态测试。
- 区分离线测试、真实主站测试、真实中心和游戏客户端验证。

技能不会自动批准外部登记、生产换钥、部署或上传凭证；也不应为用户已经授权的本地工作反复请求确认。

## 首版行为复核场景

详细场景见[验收参考](../skills/union-skill/references/acceptance.md)。后续修改技能时至少复核：

| 输入场景 | 合理决策 |
| --- | --- |
| 已有 Yggdrasil，没有密钥热更新 | 网关独立持钥可行，不强制先改主站密钥管理 |
| 只有 OAuth userinfo，没有 join 会话 | 明确补安全会话能力，不伪造进服成功 |
| 内部角色使用整数主键 | 保留目标模型，按需要映射 Minecraft UUID |
| 历史 sidecar 只同步版本并丢弃私钥 | 识别未实现签名数据面，不能称为进服网关 |
| 论坛只要 Union OAuth 登录 | 做依赖方授权，不部署成员材质签名网关 |
| 无中心源码和成员凭证 | 完成本地已授权工作，真实互通保持待验 |
| 只改 hasJoined 的 UUID | 指出全链路身份不一致并要求完整映射或缩小范围 |

这些是待执行的行为评估用例，不能因写入文档就报告模型已通过独立评测。实际评估应给测试者最小输入，不提前提供预期结论；报告放 reports/，不保存真实凭证。

## 维护

协议变化先更新证据和 references/union-protocol.md，再同步受影响的实现、fixture 与技能指引。Element Skin 专属事实留在本仓库适配清单，不加入通用技能硬约束。

技能文件使用 UTF-8。更新后运行 skill-creator 提供的 quick_validate.py，检查前置元数据、名称和未完成 scaffold；检查所有相对链接，再按本页场景检查行为。结构验证通过不等于真实 Union 适配已验收。
