# Docker 部署与远端验收

## 当前能力和验收边界

0.1.0 提供可运行的认证网关：Yggdrasil 登录与会话代理、材质重签、独立密钥代次、Union 成员回调、角色全量对账、可选 Webhook、管理命令、健康检查和脱敏日志。

首阶段仅支持名称和 UUID 均无冲突、未发生跨站身份映射的角色。Union OAuth、绑定和联合黑名单管理没有启用；不伪装 PHP 插件版本或声明未实现功能。真实 Union 对非 Blessing 网关版本、功能声明和回调的接受情况必须在远端验证。

运行镜像为 Linux amd64，静态 Go 程序、Mozilla CA 信任包和受限运行目录，使用 UID/GID 10001，不包含 shell。不要使用 docker exec ... sh，管理操作直接执行 /app/union-gateway。

## 离线部署包

解压发布的 docker.zip，核对包外 SHA256 和包内 SHA256SUMS，然后导入镜像：

    sha256sum -c SHA256SUMS
    docker load -i element-skin-union-gateway-0.1.0-linux-amd64.image.tar.gz
    cp config.yaml.example config.yaml
    mkdir -p secrets
    chmod 700 secrets
    umask 077
    docker run --rm element-skin-union-gateway:0.1.0 generate-secret > secrets/admin-token

导入后可先运行 python scripts/smoke.py，使用临时容器和合成配置检查镜像。该检查不会接入真实中心，结束后删除自己创建的容器和卷。

把主站签发的应用 client secret 写入 secrets/client-secret。不要把真实配置或 secret 提交到仓库，也不要把密码放在命令行参数中。容器内 UID 10001 必须能读取这些文件；在 Linux 服务器可将 secrets 目录及内部文件的所有者设为 10001:10001，目录权限 700、文件权限 600。

包内 compose.yaml 直接使用已加载镜像，不会从源码重新构建。仓库中的 compose.yaml 则同时提供 build，联网开发环境可执行 docker compose build。

## Element Skin 应用配置

在主站创建机密 OAuth 应用，启用 Client Credentials，申请并由管理员授予 profile.read.any。仅订阅和同步本地角色不需要 minecraft_profile.read.public 或用户授权码流程；网关通过 /v2/admin/profiles 回查权威资料。

配置示例中的 service_client_id 必须替换为实际应用 ID。client secret 使用文件或 UNION_GATEWAY_CLIENT_SECRET 环境变量，应用需要处于主站允许签发服务 token 的有效状态。

config.yaml 中需要填写：

| 字段 | 示例与说明 |
| --- | --- |
| public_root | 已登记的 HTTPS 网关根，如 https://union.example.org；支持经登记的子路径 |
| elementskin_api_url | 可从容器访问的主站后端根，如 http://element-skin:8080，不追加 /api/yggdrasil |
| elementskin_site_url | 用户访问的 HTTPS 主站页面根 |
| service_client_id | 主站机密应用的实际 ID |
| service_client_secret_file | 容器中可读的 ./secrets/client-secret |
| admin_token_file | 容器中可读的 ./secrets/admin-token，至少 32 字符 |
| member_key_file | 初次登记前可为空；已有成员 key 可通过此文件作为首次启动种子 |
| state_path / secret_dir | 保持 ./data/gateway.db 和 ./data/secrets，持久化在命名卷 |
| skin_domains | 主站材质使用独立 CDN 时，填写其域名；只写 hostname |

容器中的 localhost 指容器自己。如果主站在另一个 Compose 项目，应接入共同 Docker 网络并使用服务名，或配置明确可达的宿主地址；不要修改 public_root 来解决内部连通问题。

生产中心固定为 https://skin.mualliance.ltd/api/union。没有可配置的任意 hub_url。

## 启动与 HTTPS

    docker compose run --rm gateway check-config
    docker compose up -d
    docker compose logs --tail=100 gateway
    docker compose exec gateway /app/union-gateway admin -action status

配置文件与 secrets 只读挂载；data 命名卷保存 SQLite、密钥和成员凭证。首次启动没有 Union 凭证或共享密钥时，进程仍能接收中心 bootstrap 回调，但 ready 为 false。

使用 deploy/nginx.conf.example 配置 HTTPS，替换域名和证书路径。对外整个已登记成员根路由到网关，不把 /api/yggdrasil 转回主站。public_root 含子路径时，Nginx 保留该前缀，网关自行匹配；不要再 strip prefix。

默认容器端口只发布到宿主 127.0.0.1:8267，外部通过 HTTPS 反向代理访问。网关不信任任意 X-Forwarded-For 来决定权限；当前主站自身没有严格的 hasJoined ip 参数检查，此版本不宣称提供额外 IP 绑定保证。

## 成员登记与首次同步

向 Union 管理方登记 public_root 和组织代码，并明确本程序是 element-skin-union-gateway/0.1.0。不要提交主站 API 内网地址。服务器时钟需准确同步，以满足中心回调 now-10 秒到 now+30 秒的签名窗口。

网关公开 hello、接收中心签名回调，并每分钟尝试刷新目录和共享密钥。没有成员 key 时不会用空凭证向中心写角色。

中心发下 updatebackendkey 后凭证会持久化。随后可等待后台初始化，或执行：

    docker compose exec gateway /app/union-gateway admin -action refresh-directory
    docker compose exec gateway /app/union-gateway admin -action refresh-key
    docker compose exec gateway /app/union-gateway admin -action sync
    docker compose exec gateway /app/union-gateway admin -action status
    docker compose exec gateway /app/union-gateway admin -action diagnose

状态中的 active_key_version 是实际生效版本，public_key_fingerprint 是 DER 公钥 SHA256；不返回私钥或成员 key。ready 需要成员凭证、有效共享密钥、目录和至少一次已提交角色同步，仍不代表真实进服已验证。

## 角色同步与 Webhook

后台默认每 300 秒完整读取主站角色并向中心发送 UUID→角色名快照。读取任一页失败不会发送部分列表。每次中心同步成功后，才更新本地同步索引。

本版用可恢复的“请求全量对账”代次合并事件，不发送猜测性增量补偿。失败以 5 秒起步退避，最多 5 分钟；每角色当前状态由主站最新完整枚举决定，重复或乱序事件不会用旧载荷复活角色。

Webhook 可选。主站服务应用上配置公网 HTTPS endpoint：

    https://union.example.org/webhooks/elementskin

订阅 profile.created、profile.updated、profile.deleted，把主站实际发放的 signing_secret 写入本地 secret 文件并设置 webhook_secret_file 后重启。带 public_root 子路径时，endpoint 也包含此前缀。

验证 Webhook-Timestamp 毫秒时间戳、v1=hex HMAC-SHA256 和 Webhook-Id。事件去重与请求代次在 SQLite 同一事务中提交，返回 202 后由网关负责同步。未配置 secret 时 endpoint 返回 503，不降级为 Bearer secret。

主站禁止内网和回环 Webhook 目标，不能为 sidecar 临时放开该限制。没有 Webhook 时仍可依靠轮询和手动 sync。

## 启动器和服务器

启动器添加认证地址：

    https://union.example.org/api/yggdrasil

Minecraft 服务器使用 Union 联合认证地址：

    https://skin.mualliance.ltd/api/union/yggdrasil

不要让本次联调启动器继续使用主站原生认证根。元数据、公钥发现和重签均由网关提供；profilePropertyKeys 使用 Union 公钥，playerCertificateKeys 为空，不声明聊天证书签发能力。

网关要求客户端 join 经过网关。SQLite 只保存 serverId 哈希、角色和过期时间；原 token 只在内存中保留至本次 join 发出后的 25 秒，最多 4096 条。hasJoined 会先向主站 validate 复核原 token，再核对主站会话和角色，并在签名前再次检查短期关联。账号需要主站正常的 token validate 与进服权限。

该窗口短于当前主站 30 秒会话，避免会话到期后落入 fallback。记录本身不替代主站授权，重启后短期 token 不恢复，未完成的握手需重新 join。这样，token 已撤销或不是本次网关进服的 fallback 响应不会得到重签。

每次对外认证资料与签名前会核对中心 mapped 身份。如果当前 UUID 或名称需要转换，操作明确失败。中心 remapuuid 回调返回 501，并持久化阻止受影响原角色通过网关，避免错误身份登录；本版没有自动解除或映射功能。

## 管理 API 与诊断

管理 API 使用独立 Bearer admin token：

| Method | Path | 用途 |
| --- | --- | --- |
| GET | /admin/status | 版本、生效代次、目录、同步及就绪状态 |
| POST | /admin/refresh-directory | 刷新成员目录 |
| POST | /admin/refresh-key | 校验并启用共享密钥 |
| POST | /admin/sync | 同步完整角色集合 |
| POST | /admin/diagnose | 请求中心诊断，只返回中心状态码 |

失败的管理鉴权有速率限制。用户 OAuth token 不提供管理权限。

每个请求的 X-Request-ID 可与 JSON 日志对应；日志只记录 method、路由模板、状态和耗时，不记录 query、原始 URL、请求体、Authorization、cookie 或上游响应。后台失败只记录受控错误码。

| 现象 | 排查 |
| --- | --- |
| live 为 200，ready 为 503 | 检查成员凭证、共享密钥、目录和同步状态 |
| profile_sync_failed | 检查主站服务应用、scope、审核状态和容器上游连通性，再执行 sync |
| key_refresh_failed | 检查成员凭证和中心可达性；换钥失败保持旧代次，不会报告新版本成功 |
| 登录或进服返回 403 identity unavailable | 检查同步索引、中心 mapped 身份、角色冲突或 remap 记录 |
| 中心回调返回 403 | 检查时钟、原始 body 是否被代理改写、验签公钥获取及 nonce 重放 |
| 皮肤不可见 | 检查启动器认证根、元数据公钥、实际材质域名和客户端公钥缓存 |
| 主站封禁后仍需确认行为 | 在真实服务器验证主站 join 权限和 hasJoined 拒绝，不以登录成功代替进服授权 |

enable_query_email 默认 false。只有在明确授权向中心提供角色所有者邮箱后才开启；请求必须经过中心签名验证。不因此声明 unionBlacklist 功能。

## 持久化与更新

备份 data 卷中的 SQLite 与 secrets 目录，采用停机后的一致副本。它们共同构成恢复状态，不能只备份数据库。外部初始 member_key_file 仅在数据库没有已提交凭证时使用；后续中心更新的持久化凭证优先。

共享密钥文件先落盘，再提交 active 指针，最后发布内存快照。文件或数据库失败不会改变已生效代次。极端故障可能留下未被引用的候选 secret 文件，它不参与签名；维护时只依据数据库引用关系清理，不凭文件时间自动删除。

升级镜像后保留同一个命名卷，执行 docker compose up -d。本版为单实例，不要同时启动两个容器共用此卷。轮换 admin token、服务应用 secret 或 Webhook secret 后重启进程。

中心共享私钥的轮换不保证已启动客户端自动刷新公钥；双钥过渡和撤销行为仍需中心配合验证。

## 远端验收记录

使用获准测试成员和无冲突专用角色。至少记录：正常登录和刷新、join/hasJoined、无权限拒绝、客户端与中心 UUID/名称一致、皮肤和披风可见、重复 Webhook、重启后的状态恢复。

本地协议测试、容器启动成功、hello 和角色同步成功分别记录，不能写成“真实 Union 联合进服通过”。远端测试报告放 reports/，只保留脱敏证据。

## 源码构建和离线打包

联网环境：

    docker compose build

有 Go 1.26.5、Python 3.11 及以上和 Docker 的开发环境也可先静态交叉构建 Linux amd64，再打离线包：

    CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o bin/union-gateway ./cmd/union-gateway
    python scripts/package.py --binary bin/union-gateway --version 0.1.0 --output dist

打包程序从同一 Dockerfile 提取 runtime stage，不另维护一套镜像配置；scratch 镜像打包无需拉基础镜像。默认获取并校验 curl.se 发布的 Mozilla CA bundle，也可用 --ca-bundle 指定已验证的公共 CA 文件。不要把服务器私有信任根或私钥混入公开镜像。
