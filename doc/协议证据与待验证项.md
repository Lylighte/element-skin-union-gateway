# Union 协议证据与待验证项

## 证据等级

| 标记 | 含义 | 可以支持的结论 |
| --- | --- | --- |
| F 源码事实 | 指定版本客户端的代码 | 客户端的路由、请求和本地处理行为 |
| O HTTP 观察 | 指定日期公开 endpoint 的响应 | 当次状态和字段，不是未来保证 |
| D 设计决定 | 本仓库选择 | 预期实现，不是中心协议事实 |
| U 待验证 | 需要中心或真实客户端 | 不能用本地 mock 宣称已成立 |

通用协议只在[技能协议参考](../skills/union-skill/references/union-protocol.md)维护。新增发现应记录证据及范围，避免同时维护多份互相漂移的字段表。

## 公开接口观察

观察日期为 2026-10-25，仅 GET 公开接口；没有使用成员凭证、没有拉取私钥、没有向中心写入数据。

| URL | 状态和结果 |
| --- | --- |
| https://skin.mualliance.ltd/api/union | 200；servers 共 53 项、version=781、privateKeyVersion=1、meta、union_host_signature_public_key |
| https://skin.mualliance.ltd/api/union/yggdrasil | 200；根响应只有 signaturePublicKey |
| https://skin.mualliance.ltd/api/yggdrasil | 200；meta、skinDomains、signaturePublickey |
| https://skin.mualliance.ltd/api/union/member | 200；版本 6.1.0-0.3.2，serverListVersion="781"，privateKeyVersion="1" |
| https://skin.mualliance.ltd/api/union/oauth2/backend | 200；publicKey |

当次两个 Yggdrasil 入口的材质公钥相同，中心回调验签公钥不同。53 项不是 53 个唯一 code，目录可有同 code 的不同根地址。以上数量、版本、功能和字段均不可写入生产常量或当作测试黄金数据。

公开目录含带子路径的 bs_root。该观察支持“已登记根可以含路径”，不能证明中心允许自定义每个回调的完整 URL。

## 已采用的设计决定

- D 网关独立持有共享私钥并重签，Element Skin 不必先具备密钥热更新。
- D 首阶段原样使用本地 UUID 与角色名，只支持无冲突、未绑定角色。
- D 密钥、目录、角色同步状态持久化；生效状态不能只记录下载版本。
- D 生产中心固定为 skin.mualliance.ltd；测试使用依赖注入。
- D unsupported 回调明确失败，不用空成功掩盖未实现能力。

## 真实中心待验证

| 编号 | 问题 | 需要的证据 |
| --- | --- | --- |
| U01 | 非 Blessing 成员及诚实版本号是否被接受 | 获准测试成员的登记和 hello 检查结果 |
| U02 | 中心实际访问哪些路径、如何携带 username/serverId/ip | 脱敏中心回调记录及匹配的成功或失败响应 |
| U03 | 初次登记是否立即触发 remapuuid、queryemail 等 | 登记诊断及对应成员回调 |
| U04 | 更新和重复同步的精确错误语义 | 受控测试角色的新增、改名、重复请求和删除结果 |
| U05 | 密钥轮换及客户端缓存如何过渡 | 获准轮换测试或中心维护方明确契约 |
| U06 | 域名列表是否涵盖 CDN | 跨成员客户端实际材质下载及签名验证 |
| U07 | 30 秒主站进服会话是否满足时延 | 真实 join 到 hasJoined 的脱敏时间记录 |
| U08 | 无冲突角色是否仍发生名称或 UUID 映射 | 登录、主站响应、中心结果、游戏内身份的逐字段比较 |
| U09 | 联合黑名单和邮箱查询是否为首阶段准入条件 | 中心准入结果、所需权限和个人信息传输约束 |

## 记录规则

后续联调报告放 reports/，包含日期、源码版本、用例、精确结果和失败状态。不得保存真实 access token、member key、cookie、邮箱、密码、私钥或原始完整认证请求。公共响应也要避免无意义地持久化完整成员目录。

官方文档适合确认用户流程，但无法代替具体版本代码。旧文档中的“IP 验证”“无需担心共享私钥”或“remap 已弃用”等表述必须结合代码和威胁范围判断。
