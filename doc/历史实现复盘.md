# 已归档 Union 服务实现复盘

## 定位

elementskin-union-svc 是已归档的历史尝试。本复盘只记录代码中能确认的技术状态，不推断归档原因，不把旧文档当成中心权威协议，也不计划恢复该仓库。

参考提交为 585a65ff264718d56242d4938b9e76ad97c245ce。旧代码主要实现成员管理、角色同步、网页授权、绑定和管理页面；没有形成独立的联合进服数据面。

## 已确认问题

| 位置 | 代码事实 | 对本项目的约束 |
| --- | --- | --- |
| internal/server/server.go 的 routes | 没有 Yggdrasil authenticate、join、hasJoined 或材质签名代理 | 首个实现目标是完整游戏认证链路，管理 UI 后置 |
| internal/server/inbound.go 的 handleUpdatePrivateKey | 丢弃 FetchPrivateKey 返回的 PEM，只写 private_key_version；日志要求人工替换 skin-backend PEM | 网关必须实际持有和启用共享密钥，不能只同步版本号 |
| internal/server/admin_ops.go 的 handleAdminUpdateKey | 同样丢弃私钥、写版本并返回成功 | 管理入口与中心回调必须复用同一换钥业务 |
| inbound.go、admin_ops.go 的全量同步 | 使用 profileList[p.Name]=p.ID | 按 PHP 基线改为 UUID→name；fixture 独立于旧测试 |
| internal/bridge/elementskin.go | 用户端点仍调用 /v1/users/me 和 /v1/users/me/profiles | 当前只实现已存在的 /v2 API，不保留兼容分支 |
| 同文件的列表分页 | 请求发送 next_cursor，当前主站读取 cursor | 多页测试检查精确 query 和无重复条目 |
| doc/Go实现手册.md | 将 remapuuid 写为已弃用，当前 PHP 参考仍注册并实现 | 不能由旧说明推断中心已废弃；首阶段明确限制 |

旧 sync 测试用模拟 Hub 断言了 name→UUID。实现与测试一致不代表协议正确，这类测试需要从独立协议证据构造预期请求。

旧项目的 OAuth2 RSA 4096 密钥属于跨站用户信息签名，不能把它已有的生成和轮换功能当作 Union 材质私钥已经生效。

## 可参考的部分

- 中心 HTTP 请求和 X-Union-Member-Key 的封装边界。
- 目录拉取、中心回调原始体验签、nonce 存储的业务划分。
- 角色创建、改名、删除的成员通知入口。
- 服务应用获取 token、事件验签和持久化的组织方式。

这些部分仍需按当前协议、主站接口和错误路径逐项重写或验证。引用代码前核对许可证；不整体复制旧管理后台、OAuth 网页会话及多格式兼容逻辑。

## 新实现的验收顺序

先验证主站的认证与 join/hasJoined 代理，再验证出口签名和密钥恢复，然后形成目录和同步闭环，最后用获准成员做真实游戏测试。成员 hello、管理状态、同步或诊断成功单独记录，均不能标记“已完成联合进服”。
