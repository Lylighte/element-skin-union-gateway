# Union 网关测试与联调计划

## 当前阶段

M0 仅交付仓库、设计文档和 union-skill。当前没有 Go 模块或运行程序，不运行不存在的构建命令，不将技能结构检查写为网关功能测试通过。

后续 Go 实现使用 gofmt、go test ./...、go vet ./...；涉及签名快照、worker 与并发回调时运行 go test -race ./...。引入运行代码时固定跨包 coverage 统计方式，整体语句覆盖目标不少于 90%，不能靠弱断言达成。

## Fixture 与独立预期

测试 payload、角色列表、错误对象放在对应 testdata 中；密钥由测试运行时生成，不提交 PEM、真实 token 或中心凭证。模拟成员数据使用合成 UUID 和名称，不复制整个远程目录。

精确请求预期从[协议参考](../skills/union-skill/references/union-protocol.md)及源代码证据独立构造。禁止让被测 mapper 和 mock 共同计算同一个“预期值”，尤其是 profileList 方向、签名字节和分页 query。

## 代理与身份

| 用例 | 精确断言 |
| --- | --- |
| 登录与刷新 | method、完整上游 path、body 字段、clientToken、selectedProfile 和状态码 |
| 无效口令或 token | 上游 Yggdrasil 错误和对外状态一致，无本地成功 session |
| join 正常和拒绝 | accessToken、selectedProfile、serverId 一致；拒绝不建立可用状态 |
| hasJoined | 正确请求只返回对应本地角色；错误名字、serverId、过期会话无成功资料 |
| profile 和批量查询 | UUID、名称、顺序及 unsigned 语义；外部 fallback 角色不重签 |
| 反向代理 | 未登记路由不转发；外部重定向不带出 token；API location 指向网关 |
| 错误上游 | 超时、非 JSON、超大 body、缺字段不生成成功 profile 或签名 |
| 身份限制 | 冲突和绑定状态明确失败，不修改主站角色或存档身份 |

当前主站 join 会话为 30 秒；边界用可控时钟验证到期，真实联调记录实际时延。IP 语义按实际实现逐项验证，不把 header 转发写成已完成 IP 校验。

## 密钥与属性

- 对成功输出使用当前 Union 公钥验签，并检查原始 value 字节、Base64 编码、skin/cape URL 与 slim metadata。
- metadata、公钥发现、签名和 hello 使用同一 active 代次，不泄露私钥。
- 无效 PEM、错误算法、公私钥不匹配、版本回退及同版本不同指纹精确拒绝。
- 拉取失败、文件写失败、数据库提交失败保留旧 active；失败不修改 hello 生效版本。
- 新代次文件落盘但事务未提交、事务提交后进程退出、重启加载缺文件等情况分别验证，不能自动生成自有钥作为 Union 钥。
- 并发更新和请求保持单请求快照一致；测试公开元数据的客户端缓存边界，不能假定双钥过渡存在。
- 成员凭证更新后下一次真实中心请求使用新值，失败更新不改正在使用的凭证。

## 回调与同步

| 用例 | 精确断言 |
| --- | --- |
| 正确中心签名 | 使用原始 body、timestamp、nonce；业务只执行一次 |
| 错签、缺头、过期或未来超窗 | 明确拒绝；目录、密钥、凭证与任务均不变 |
| 并发同 nonce | 仅一个请求占用成功；其他请求无副作用 |
| nonce 持久化失败 | 不执行修改 |
| 全量多页 | 每页请求 cursor 正确、结果无重页；中心收到 UUID→name |
| 任一页失败 | 中心未收到部分全量 |
| 首次全量与并发事件 | 对账后收敛，不丢失新角色或保留已删除角色 |
| 事件重复与乱序 | 不重复副作用，不由旧事件复活删除 |
| 主站回查失败 | 重试任务，不能推断删除 |
| 中心暂时失败 | 持久化退避重试，有界资源使用 |
| 重启 worker | 恢复待处理任务，已确认任务不重复错误写入 |
| 未实现回调 | 明确失败，不假报功能或成功 |

Webhook 验签要使用主站当前信封和实际发放 secret；“Bearer secret”不是当前主站签名协议的替代。公网 HTTPS 接收端的网络策略也应与主站校验一致。

## 真实联调步骤

使用获准登记的测试成员和专用测试账号，先只同步合成角色。真实中心的新增、删除、成员凭证及轮换操作依用户已有授权范围执行。

1. 在真实 Element Skin 验证正常和错误登录、刷新、角色选择、join、hasJoined 与权限拒绝。
2. 完成中心登记，观察 hello、目录、密钥、成员凭证和诊断请求，记录精确字段类型。
3. 全量及增量同步测试角色，确认中心查询的 name、UUID 与本地一致且未产生映射。
4. 启动器添加网关认证根，服务器使用联合认证根；比较客户端、主站、中心与服务器身份。
5. 验证登录、进服、退出后重进、皮肤与披风，并从另一成员客户端检查材质接受情况。
6. 撤销测试角色 join 权限或执行目标定义的封禁，确认联合链路仍拒绝。
7. 按已确认规则清理测试角色和数据；记录失败、恢复过程及未覆盖项。

签名轮换测试只在获准隔离环境或中心配合下进行，不触发整个 Union 的生产轮换。无法完成时保留未验证状态，而不是借模拟结果标记通过。

## 报告格式

reports/ 下的报告至少记录日期、各组件版本、测试环境、用例、期望与实际、状态和后续问题。真实数据使用固定脱敏标识，不包含密码、token、member key、cookie、邮箱、私钥或完整认证抓包。

“真实进服完成”要求有效角色成功、无权限角色拒绝、身份一致且材质可接受。仅有同步、hello、诊断或 mock E2E 结果不能达到这一状态。
