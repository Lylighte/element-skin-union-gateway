# Union 适配验收与技能行为场景

## 功能验证层次

1. 静态检查确认真实能力、路由、权限和状态所有者。
2. 目标站适配器测试精确的 method、path、query、body 和错误映射。
3. 网关集成测试使用可控依赖，验证签名、同步与失败后的状态。
4. 真实目标站验证有效登录、刷新、角色归属和进服拒绝。
5. 获准 Union 测试成员与真实游戏客户端验证联合进服和材质。

每层只支持自身结论。测试全部通过也不能自动证明中心接受非 Blessing 成员。

## 关键断言

| 场景 | 必须验证的结果 |
| --- | --- |
| 上游认证拒绝 | 对外拒绝，不生成本地成功 token |
| 错误角色、无 join 权限或受限账号 | join 被拒绝，不留下可用进服会话 |
| 未 join、会话过期或 serverId 错误 | 无成功 hasJoined，不签任意 profile |
| 非本地 fallback 角色 | 不用当前成员密钥重签 |
| 材质重签 | Union 公钥验证通过；原上游公钥不被错误声明为出口钥 |
| 同时换钥和请求 | 单次响应的签名、公钥与代次一致 |
| PEM 无效、版本回退或指纹不匹配 | active 状态、当前文件引用和生效版本不变 |
| 写盘、数据库提交或进程重启边界 | 从最后提交状态恢复；不报告未生效版本 |
| 回调签名错误、过期、并发重复 nonce | 不产生未授权或重复副作用 |
| 全量多页 | 每页 cursor 精确，payload 为 UUID→name，没有重复页 |
| 任一分页失败 | 不向中心提交部分权威快照 |
| 创建、改名、删除事件重复和乱序 | 当前权威状态收敛，删除不被旧事件复活 |
| 身份映射 | 登录到材质载荷全部一致，反向 join 使用本地正确角色 |
| 未实现功能 | 不声明 enabled，不返回伪成功 |

错误断言应覆盖状态码、协议错误对象和数据库、缓存、文件副作用。只检查“没报错”“长度大于零”不足以证明功能。

测试数据、key 和 token 使用合成数据；密钥运行时生成。不要让实现与模拟中心共同依赖同一个错误 fixture，尤其是全量同步映射方向。

## 技能行为场景

这些场景用于复核技能的决策能力。给评估者技能和最小目标资料，要求它说明适配方案及所需实现；不要事先给它下方判定。记录实际行为，再判断是否达到要求。

### 已有 Yggdrasil 但没有密钥热更新

用户要求先建独立网关，目标站提供认证、角色查询、join/hasJoined，密钥仅启动加载。

应选择可行的外置签名边界，维持目标站权威，不把主站先建设密钥版本管理列为必需条件；同时明确网关仍要管理实际生效密钥和元数据。

### 只有 OAuth 用户资料的皮肤站

目标站可获取账户和皮肤 URL，没有 token 与角色绑定的进服会话。

应指出缺少权威 join/hasJoined 或等价能力，提出最小扩展。不能拿 OAuth userinfo 200 或公开 profile 200 伪造进服成功。

### 使用整数主键的另一种架构

目标站的内部角色主键是整数，Minecraft UUID 为独立列，使用自己的权限和事务系统。

应复用该模型和栈，明确 ID 映射，不要求迁移到 Element Skin 的 UUID 主键或 OAuth scope 名称。

### 历史 sidecar 能同步但丢弃私钥

资料给出成员控制路由、同步管理页面、FetchPrivateKey 返回值被丢弃，且没有游戏认证代理。

应识别数据面与签名缺口，不把“密钥版本已更新”或成员诊断成功当成联合进服完成。

### 只让网站使用 Union OAuth

用户要把自己的论坛登录按钮接到 Union OAuth。

应处理依赖方授权码流程、state 和实际用户信息契约，不要求取得材质私钥或注册成员站。

### 没有中心源码和生产凭证

用户授权本地实现，提供官方成员源码，但没有成员 key。

应完成可验证的离线实现与测试，列出真实中心剩余项，不要求提供不可获得源码，不触碰真实中心写入，也不宣称真实互通。

### 网关只改 hasJoined 的 UUID

目标系统登录时发本地 UUID，计划只在服务器响应时替换成绑定 UUID。

应发现 1.19+ 身份一致性问题，要求贯穿登录、刷新、角色选择、join、profile 与材质字段的映射，或明确缩小到无映射角色。

## 真实联调报告

记录目标版本、成员配置的非敏感部分、用例、HTTP 状态、身份字段比较、客户端版本及材质结果。把真实身份替换为稳定的测试标识，不保存密码、token、member key、cookie 或私钥。

真实成功至少包括：有效角色加入 Union 服务器；无权限角色被拒绝；同一角色客户端、目标站、中心和服务器身份一致；皮肤与披风签名和域名均可接受。
