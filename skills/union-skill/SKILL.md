# Union 皮肤站适配

先检查目标皮肤站的实际认证、角色和会话能力，再选择适配方式。目标是可验证的联合认证链路；成员 hello、同步成功或管理页面可用不能替代进服成功。

保持用户指定的架构、语言、交付范围及既有授权。用户只要求研判或初始化文档时，交付相应结果；不要自动部署、登记成员、改生产密钥或扩展到 Union OAuth 和黑名单管理。

## 明确接入角色

- 成员皮肤站：用户仍向自己的皮肤站登录，游戏服务器通过 Union 验证；需要本技能的成员协议与数据面适配。
- Union OAuth 依赖方：网站借助 Union 登录；不因此需要材质共享私钥、角色同步或 Yggdrasil 网关。
- 联合认证消费方：游戏服务器或聚合认证服务使用中心联合入口；不因此成为成员站。

意图已能从用户请求和仓库推断时直接推进。缺少资料只影响后续联调时，先完成离线分析或实现，不要求用户提供不可获得的中心源码。

## 检查目标能力

读取仓库指令、认证与 session 代码、角色数据模型、公开元数据、公钥、权限、事件和部署配置。只读最小必要文件，不打开真实 secret 或 token 缓存。

记录真实 endpoint、方法、参数、返回类型、权限和状态语义，而非根据框架名称推断。重点确认：

- 是否有权威 authenticate/refresh、join/hasJoined 或等价的安全会话能力。
- 角色所有者、稳定 ID、大小写和改名策略，能否完整枚举及处理删除。
- 哪一层执行封禁和 join 权限，认证代理是否保留该判断。
- 材质 payload、签名算法、允许域名与公钥发现方式。
- 外置应用权限、分页与事件机制，以及网络访问限制。

能力不足时明确需要新增的最小主站接口，不把“能查角色”误判为“能验证进服”。

## 依据证据决定架构

先读 [Union 协议参考](references/union-protocol.md)，具体架构判断读 [适配架构](references/adapter-design.md)。

区分指定版本成员源码事实、公开接口观察、设计选择和待验证中心行为。中心源码不可用时，可以实现参考成员对外行为并离线验证；中心路由、错误码、重试和成员准入保留为真实联调项。

生产中心是 https://skin.mualliance.ltd；控制根 /api/union、联合认证入口 /api/union/yggdrasil、MUA 本站入口 /api/yggdrasil 用途不同。内部主站地址可配置，对外登记根和协议后缀必须满足中心。

若用户选择外置网关且目标站已有安全认证会话，优先让网关持有 Union 私钥并重签。目标站没有密钥版本接口不自动成为阻塞；若方案需要它实际签 Union 密钥，则必须设计生效与恢复。

不要强制其他架构改用 Element Skin 的 OAuth、数据库、角色 ID 或目录结构。具体适配器贴合目标栈，复用它已有的权限与事务。

## 实现与验证

按用户范围实现最短的完整链路，同时覆盖对应失败状态。协议中的关键约束：

- 全量 profileList 是 UUID→角色名；完整取完分页才提交，失败不提交部分全量。
- 中心回调验签使用原始 body + timestamp + nonce，RSA-SHA256；防重放使用原子占用。
- 材质签名使用 properties.value 原始 Base64 文本，RSA-SHA1；只重签经过本地权威验证的角色。
- 当前生效密钥、公钥元数据和签名响应来自一致代次，不能把下载版本报为生效版本。
- 身份映射必须贯穿登录、刷新、角色选择、join、hasJoined 和材质内部字段；只替换返回 UUID 不成立。
- 功能声明、支持的回调和版本信息必须真实。发现旧适配中所谓“弃用”说明时核对当前参考客户端。
- 共享材质私钥不能复用到站点 JWT/OIDC、Union OAuth 或 Webhook。

正式编码或验收时读 [验收与行为场景](references/acceptance.md)。用目标站测试或真实实例验证权限与会话，在模拟中心上验证精确请求，再在获准成员上验证真实联合进服。不要默认生产凭证或写入真实中心来完成本地测试。

角色事件只表示变更提示。通过回查和对账处理重复、乱序、重命名和删除；本地 worker 需要明确的持久化和重试责任。

首阶段若限定无冲突角色，检测并报告不支持的映射状态，不暗中宣称绑定和冲突场景也已完成。

## 交付

交付用户要求的代码或文档，附适配矩阵、必要配置、已运行验证和剩余联调项。适配矩阵至少说明账号认证权威、会话权威、角色来源、签名持有者、外部路径与身份映射位置。

只在实际链路成功后报告“真实 Union 进服已验证”。缺少成员凭证或登记只阻塞真实中心验收，不妨碍完成已授权的本地实现。技能不授予额外的外部操作权限，也不要求对已获授权动作重复确认。
